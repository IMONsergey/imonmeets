## Safe app-only rollback

Run on imon-workstation if the candidate app must be reverted:

/home/sergey/.config/imonmeets-accounts/cutover-20261102T124640Z/rollback-app-image.sh

The script has been syntax-checked and its Compose resolution was dry-validated. It was not executed.

It:

- switches only the app service to imonmeets-app:91aae88;
- retains APP_URL https://meets.imon.world:8443;
- keeps REGISTRATION_ENABLED=false;
- sets EMAIL_DELIVERY_MODE=capture and EMAIL_PROVIDER=smtp because the previous image does not implement the Resend HTTPS transport;
- uses docker compose up -d --no-deps app.

It does not recreate PostgreSQL, Redis, LiveKit, Egress, TURN or recording storage. It does not restore or roll back the database. The new im_email_deliveries table is additive and can remain unused by the old app. All data created since cutover remains in place.

Do not restore env.before wholesale as part of app rollback: that file contains the previous public origin and previous image selection. Do not run docker compose down -v. Do not restore a pre-cutover database dump over current data.

The new nginx vhost and TLS certificate can remain in place during an app-only rollback. Existing trusted proxy secret is retained and the ingress continues to proxy to the app service.

Rolling back only Vercel does not roll back the backend or database. Use the app-only helper for backend image rollback.
