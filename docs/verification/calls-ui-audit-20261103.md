# IMON Meets: звонки, интерфейс и браузерная готовность

Дата: 2026-11-03. Исходный release: ddd429bf92b889b8ed424e345cf80b4b3e620c34. Изолированная ветка: fix/calls-ui-audit-20261103. Все действия выполнены через Remote Desktop Commander; production, DNS, реальные встречи и общая release-ветка не менялись.

Этот отчет объединяет чтение кода, проверку сохраненных свидетельств и выполненные регрессии. Он не означает, что каждый экран проверен на каждом физическом устройстве или что весь продукт готов к продаже.

## Главный вывод

Базовые сценарии реализованы существенно дальше прототипа. Есть комнаты, расписание, гостевой вход, зал ожидания, чат, управление участниками, архив, запись с отдельными настройками и встроенный виджет. Настоящий LiveKit уже передавал синтетические звук и видео в изоляции.

Коммерческую готовность звонков пока блокируют внешняя сеть и TURN/TLS443, незавершенная браузерная приемка, реальные устройства, восстановление после сетевых сбоев и измеренная емкость продаваемых тарифов. Локальные тесты этих гарантий не заменяют.

Обнаруженная гонка отмены входа исправлена отдельными клиентским и серверным изменениями. Доказательства до и после сохранены.

## 3. Исправленная клиентская гонка

При нажатии «Отменить запрос» старый WaitingGuest продолжал ждать и обрабатывать ответы до завершения DELETE. Позднее разрешение организатора могло создать /join. Уже выполнявшийся /join мог включить call flow после отмены.

Теперь отмена немедленно останавливает polling и admission signal. Join проверяет отмену и на сетевом запросе, и при обработке результата. Даже транспорт, который доставил поздний ответ после abort, не переводит пользователя в звонок.

Если сервер не подтвердил отмену, автоматический вход остается остановленным. Пользователь может повторить отмену или вернуться к проверке устройств. Сообщение не выдает сетевой сбой за подтвержденную отмену на сервере.

Проверки:

- Обычное разрешение продолжает открывать call flow.
- Поздний waiting-status после отмены не создает /join.
- Поздний grant незавершенного /join не создает connecting/call.
- Ошибка DELETE не возобновляет автоматический вход, остается локальный выход.

Тест использует реальные React компоненты и управляемые deferred API responses. Камера/микрофон и WebSocket явно запрещены. Итоговый mobile390 PNG просмотрен; горизонтального overflow нет. Это не приемка всей доступности звонка.

Клиентский commit: d8101a32effd55e89c54f0a539a92d9588828c71. [Клиентский отчет и receipts](waiting-cancellation-20261103.md).

## 4. Серверная граница отмены

Первоначальный DELETE waiting менял status только при used_at IS NULL и всегда возвращал ok. Если /join успевал потребить ticket, JWT оставался активным. PostgreSQL regression воспроизвел это как204 вместо403 на защищенном signaling gate.

Новый код:

1. Связывает потребленный ticket с точным issued_identity в той же транзакции, где создается session.
2. Отменяет по порядку блокировок workspace → room → ticket, совпадающему с /join.
3. Отзывает только session этой комнаты, generation и identity.
4. Сохраняет точное durable задание на RemoveParticipant и повторяет его после неопределенного результата.
5. Не меняет generation, не удаляет всю комнату и не отзывает соседнюю вкладку того же guest browser.
6. Проверяет переданный waitingToken даже после отключения waiting room. Новая явная попытка без старого token по-прежнему следует текущей политике комнаты.

Для старых потребленных tickets без связи с identity возвращается409 WAITING_CANCELLATION_UNVERIFIED. Код не угадывает identity по имени, пользователю или cookie и не отзывает все похожие сессии.

Без включенной защиты signaling возвращается503 WAITING_REVOCATION_UNAVAILABLE. Локальная отмена сохраняется, но enforceable revocation не заявляется. При неопределенном RemoveParticipant возвращается503 WAITING_CANCELLATION_PENDING; отзыв credentials уже сохранен и не откатывается.

Реальный production revoke дополнительно требует закрытого прямого signaling-порта и полного прохождения всех публичных routes через authorization. Исходный флаг конфигурации и API-тест сами по себе этого не доказывают.

Итоговая изолированная проверка: 6/6 focused API tests, API typecheck и7/7 существующих moderation/suite/room-lifecycle tests прошли, skipped0. Полный root typecheck прошел предыдущим прогоном. Сохранены исходные красные тесты, промежуточные ошибки и точные SHA-256 проверенных файлов: [серверный отчет и receipts](waiting-cancellation-api-20261103.md).

Отдельно подготовлено расширение существующего real LiveKit harness для настоящего отключения отмененного participant, сохранения соседнего соединения и отказа исходного/обновленного JWT на четырех signaling routes. На момент этого отчета runtime нового сценария еще не выполнен; CALL-CANCEL-LIVE остается открытым до отдельного результата.

## 6. Что нельзя объявлять готовым по этому отчету

- Внешний TURN, Safari/iPhone/Android, надежный Firefox media.
- Длительные звонки и емкость тарифа по старому smoke на8 участников.
- Реальная запись, все операции с записью, согласие на нее и восстановление объектов.
- Персональная приватность каждой встречи: текущая модель пространства отличается от per-meeting ACL.
- Синхронный перевод: эта ветка не подключает experimental ASR/MT/TTS к продаваемому звонку.
- Развернутый новый release: код и изолированные проверки не меняли production.
